# IPC 日志系统答辩 HTML 设计说明

## 目标

制作一份约 15 页、可浏览和可编辑文字的单文件 HTML 答辩演示稿，基于《校招生实习题目：IPC日志系统设计与实现》及 HJM-fast 当前源码，覆盖题目第七节要求，并让讲解者能从架构图追到代码入口。

## 受众与叙事

面向实习导师和技术评审。叙事按“问题与验收要求 → 总体结构 → 一条日志与一条控制命令 → 排序、输出和退出边界 → 方案权衡 → 真实的 AI 协作纠偏 → 验收现状 → 收获建议与现场演示”展开。

## 内容结构

1. 封面：IPC 日志系统设计与实现。
2. 项目背景：多进程日志分散、业务线程受 I/O 影响、汇聚与可追溯要求。
3. 题目要求与实现映射：四级日志、字段格式、双输出、有界异步、FDBus 汇聚与动态调级。
4. 系统结构：name_server、log_server、多个 worker，分别标出数据面和控制面。
5. 日志端到端路径：Logger 过滤、队列、worker 发送、FDBus、server 校验、汇聚排序、Sink 输出。
6. 线程模型和资源边界：业务线程、发送线程、FDBus 回调、汇聚线程及有界队列的职责。
7. FDBus client/server 链路：服务发现、Protobuf 请求、回调入队和 ACK 的准确语义。
8. 独立动态等级控制：list、get-level、set-level 与 process_instance 定向。
9. 排序与输出：有限窗口水位、迟到边界、控制台与轮转文件。
10. 正常退出排空：worker 本地排空、server 停止接收、aggregator 排空和 Sink 刷新；说明崩溃、超时与持久化边界。
11. 关键方案比较：同步/异步、阻塞/丢弃/扩容、client/server 与替代方案、Protobuf 与自定义协议、本地与远程输出。
12. AI 协作实践：依据题目将“退出时排空”与“业务可触发的跨进程 flush 协议”区分，展示移除协议、收敛到内部 shutdown 的前后变化，并如实标注当前验证状态。
13. 问题与验收现状：F1–F5 待修，F6–F8 已修改但未在 Ubuntu 验证；当前源码完整 Linux 回归和演示待运行。
14. 收获、反思与建议：需求边界、并发和证据意识；建议明确 AT1–AT5 验收定义、预留 Linux 联调时间、提供稳定环境。
15. 演示路径与问答：列出现有演示入口和控制命令，不声称尚未执行的演示已通过。

## 事实与验证边界

- 只采用题目、架构说明、实施计划、交付 README、问题记录和当前源码中的事实。
- AT1–AT5 的具体定义在现有材料中缺失，不补造其含义或覆盖结论。
- 不把历史 Ubuntu 输出套用到当前源码；未执行的构建、双 worker 演示、控制演示及边界复验标为待验证。
- AI 案例按“人主导的需求边界纠偏”呈现；不将来源未核实的历史缺陷归因给 AI，也不把静态检查写成运行通过。
- 方案比较说明适用条件，不宣称本项目有未经测量的性能优势。
