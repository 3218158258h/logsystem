## 2. 本轮核心原则

- **按交付阶段汇报，不按本地全部实现汇报。** 今天可以只突出日志核心，不必逐项披露超前完成的控制、多进程和全部内部优化。
- **分别记录实现、验收、交付。** 已经写好的功能可列为“后续阶段交付/专项验收”，不必写成今天的成果，也不改称“尚未实现”。
- 日报“未完成”从真实未结束的阶段复验、专项检查、交付整理或正式材料中选择，并说明简短原因；不需要为了凑条目虚构故障。
- 报告与提交包使用同一阶段范围。单改文字、仍然复制整个工程，不满足本次安排。
- 主项目只在 HJM-fast 维护；阶段包是从实际源码提取的交付快照，不回退主项目功能，不修改历史日期或开发记录。
- 对外的文字简洁自然。内部的细粒度统计、故障证据、工具限制和操作历史仍保存，按需要支持日报和答辩。

1. **今天完成**只写当天阶段内实际做过的工作；不因本地提前实现而把第三、四天成果都写进第二天日报。整理和验证不能改称当日新开发。

6. 后续每日沿用本表，不能自行扩展当天范围；实际出现延期或计划调整时，先说明真实偏差并更新本表，再同步日报。不得补造历史工作或提前写未来日期的完成报告。
